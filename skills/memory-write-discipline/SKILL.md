# Memory Write Discipline

单次 `memory()` 写入前的判断：这条事实该不该存、归哪一层、怎么加载、怎么写。

## When to Use

- 准备调用 `memory()` 写单条新事实之前
- 发现一条可能值得持久化的环境事实、工具怪癖、用户偏好或流程
- 一次复杂任务结束后，决定「存哪 / 存不存」

Don't use for：批量整理、容量治理、删除归并、cron 定时整合 → `memory-cleanup`（dry-run + 审批）。本技能不授权自动删除、不授权绕过审批的写入。

## 0. 先读 live 值

- cap 读 `config.yaml` 的 `memory.memory_char_limit` / `user_char_limit`，或 `hermes memory status`。**不要用社区文档里的 2200 / 1375**。
- 阈值按比例：80% 黄线、95% 红线。
- 按**字符数**不是字节数（中文 1 字 = 3 字节），也不是 GPT 模型的 token 数（">6000 tokens" 是 `memory_char_limit` 按 token 计的旧说法，本机 6000 是字符）。
- **量当前值不要读文件字节**：`D:\Hermes\memories\MEMORY.md` 的字节数含中文 3 字节/字，会虚高约 3 倍（例：846 字符 → 1262 字节）。以 `memory()` 工具回报的 current/limit 为准；需要自己算就按字符数读，别用 `os.path.getsize`。
- MEMORY.md 接近满时，默认它没有余量：新增必须先腾出等量空间（同一个原子 batch），或改道。

## 0.5 写后容量提醒（写完必须执行）

每次 `memory()` 写入后，看工具回报的 `current/limit`，按两层判断：

| 占用 | 动作 |
|---|---|
| < 80% | 不说话，正常继续 |
| ≥ 80%（黄线） | **当轮回复末尾加一行提醒**，说明哪一层、多少字符、百分比、建议下一步（可跑 `memory-cleanup` 的 dry-run，仍需用户审批） |
| ≥ 95%（红线） | 同上提醒 + **下一次写入前先腾空间**：要么在同一 batch 里 remove/patch 等量内容，要么不写 |

阈值即 §0 那两条，不另设 60% 级别（用户 2026-11-10 明确：按 80/95 来就行，不要多一档）。

规则要点：
- 提醒**只在回复末尾一行**，不打断主任务、不单独占一轮。
- 提醒内容是事实（层名 / 当前 / 上限 / 百分比 / 建议），不是叙事。
- 这是**提醒**不是**自动清理**：`memory-cleanup` 永远要用户开口才跑，本技能不授权自动删除。
- 用户明确说过「这次不用提」才可跳过当轮；否则默认执行。
- 两个独立账本：MEMORY.md（环境/世界）和 USER.md（关于用户）各自判断，不合并算比例。

## 1. 三门

依次判断，**不得用后一维度的判据去否决前一维度**（典型错误：用「不值得每轮付 token」毙掉「值得按需保存」）。

### 门 1 · 保留价值（否决）

1. **没有未来调用价值** → 不存。判据：能不能说出未来什么场景会调用它？说不出可信场景就默认不存（不是「没有价值」）。
2. **能从权威来源低成本可靠重建** → 不存；但重建会丢决策理由 / 限定词 / 已知可用值的，保留「来源指针 + 理由」，不是裸指针。
3. **已有等价内容** → 三选一：等价则跳过；新增细节则合并；事实已变则修订原条目（不是再存一条）。

### 门 2 · 归属与作用域

先定作用域（全局 / 项目 / 领域 / 会话），再定唯一主记录。
**作用域优先于「关于谁」**：`用户要求项目 A 的注释用英文` 归项目 A，不能因「用户优先」变成全局偏好。
允许「主记录 + 指针」，但指针只证明地址存在，不证明正文会被加载。

### 门 3 · 加载方式与预算

| 加载方式 | 谁在用 | 成本口径 |
|---|---|---|
| 全局每轮注入 | MEMORY.md / USER.md / SOUL.md | 每条消息都付 |
| 作用域激活时注入 | 项目 AGENTS.md | 该作用域内每条消息都付 |
| 按需加载 / 检索 | 技能 / Hindsight | 只在命中时付 |

「愿意为它付 token 吗」只在这一步用，且按对应层的注入频率问。

### MEMORY.md · 例外入口（AND 全满足）

```
确需全局常驻 ∧ 无更合适的专门归宿 ∧ 无法可靠 offload（见 §2）
```

MEMORY.md 很小甚至为空都合理；不把它当默认收纳。

## 2. offload 判据

两条检查：

1. **交付**：用代表性查询，在**当前配置的交付时限与裁剪条件**下确认内容能进入上下文。手动 `hindsight_recall` 成功**不能单独作为自动注入成功的充分证据**——它证明内容已存储且可检索，不证明 prefetch 已完成交付。
2. **后果**：在**适用场景**中，偶发未命中的后果可接受。判据是「漏一次会怎样」，不是「影响多少轮」——一年只触发一次的发布约束，漏一次也不可接受。

**必须遵守的约束不承担唯一交付：**

- 更快 recall（当前 <5s）不改变结论：更快 ≠ 一定命中。
- 不能 offload ≠ 应该全局常驻。
- **确定性注入通道只有**：全局每轮的 MEMORY.md / USER.md / SOUL.md；作用域内每条消息的项目 AGENTS.md（前提是项目真有该文件）。
- **技能不是确定性通道**：模型按 description 自行决定是否加载，本机没有验证过任何强制触发机制。技能不能承载「必须遵守约束」的唯一交付。
- `domains/` 规则层当前未启用（只有 README，无实际领域目录），不能当落点。
- 指针不保证正文被加载：必须遵守的约束不能只留指针。

## 3. 过滤四问

| 问 | 判据维度 | 拦什么 |
|---|---|---|
| ① 有未来调用价值吗（能说出可信场景吗） | 价值 | PR#、SHA、「阶段 N 完成」、临时路径、一次性调试上下文 |
| ② 能从权威来源低成本可靠重建吗 | 可推导性 | 端口、model id、服务名、启动链细节、通用可搜事实、原始转储 |
| ③ 已有等价内容吗 | 重复 | 精确重复、语义近似、与 SOUL.md / AGENTS.md 重复注入 |
| ④ 愿意按该层注入频率付 token 吗 | 成本 | 会话临时物、极少数场合有用却想塞常驻层的东西 |

负面清单是四问的实例，不是另 12 条规则：一次性修正 / 显然事实 / 可能翻转的陈述 / 临时状态 / 任务进度 → ①；配置值 / 可搜事实 / 原始转储 → ②；精确重复 / 语义近似 / 重复注入 → ③；会话临时物 → ①+④。

**唯一例外**：「伪装成事实的祈使句」不是否决，是改写法 + 改归属：`Always respond in Chinese` → `User communicates in Chinese` → USER.md。

工具**只有精确去重，没有语义去重**：「Voce Rick speed 1.55」和「voce rick velocità 1.55」算两条。③ 必须靠写入前主动检索相似条目，不能指望工具拦。

## 4. 写法

- **声明式，不祈使式**：`✓ 用户偏好简洁回复` / `✗ 永远简洁回复`。祈使句会被当指令重读，可能盖过用户当前请求。
- 紧凑、一条一事实、`§` 分隔。
- **不写叙事**（过程、心情、执行流水、"阶段 N 完成"）。

### 日期标签：默认不加

理由不是审美，是三项实际代价：

1. **不可寻址**：`patch` 要 `old_text` 精确匹配。日期在行首时「改这条事实」退化成「连日期一起重写」；日期若自动生成，同一事实在不同会话里字符串不同，寻址直接失效。
2. **制造重复**：工具只有精确去重。`[2026-11-10] 端口 8080` 与 `[2026-11-12] 端口 8080` 算两条。
3. **预算**：`[2026-11-10] ` 约 13 字符，在每轮注入的层上是长期付账。

**决定性的一条**：日期一旦存在，下游就容易拿它当**淘汰闸门**（「超 N 天 → 陈旧 → 降级/删」）。这类实现本机出现过（memory-gc 式脚本），而本机记忆里恰好有一批**又老又硬**的条目（WMI 损坏、pip 卡死绕行、`config.yaml` 禁手改）——按年龄淘汰第一批就会干掉它们。判据只能是「漏一次会怎样」（§2），不是年龄。

时效确实关键时（版本号、价格、政策的观测时点），写在该句**行尾**并写死，以后不再改动。

- **别过度合并**：500 字 blob 比 5 条 100 字更难解析，也难被 `patch`/`remove` 单独寻址。
- 砍解释，**别砍路径 / 限制 / 命令 / 已知可用值**。
- 负向约束与具体配方**逐字保留**，不能概括掉。

## 5. 工具动作

- 只有 `add` / `patch` / `remove`，**没有 `replace`**。
- `patch` 替换的是 **span 不是整条**：重写整条要把**完整条目**作为 `old_text`，否则旧尾巴留下，越改越长还报 success。
- 多次改动放进**一个 `operations` 数组**原子执行；限制只检查 batch 最终结果。
- 别并行多个 `memory` 调用（race、usage 失真）。
- 中途写入立刻落盘，但**下个会话才进 system prompt**（冻结快照）。
- 后台 `background_review` 的 fork 只能写不能验证（无 shell）：提案一律当**未验证**；批准前算 `Σ(len(content) − len(old_text))`，净增就别批。

## 6. 落点表

归属（行）× 加载保障（列），两个独立维度：

| | 全局常驻 | 作用域激活时注入 | 按需加载 |
|---|---|---|---|
| 关于用户 | USER.md | — | 按需用户资料（不是技能） |
| 关于 agent 身份 | SOUL.md | — | — |
| 关于环境 / 世界 | MEMORY.md（例外入口） | — | 技能 / Hindsight |
| 关于项目 | — | 项目 AGENTS.md；domains 规则层（未启用） | 项目档案 / Hindsight |
| 关于「怎么做」 | — | — | 技能（非确定性交付） |

技能承载**处理资料的流程**，不承载资料本身。

## 最小规则

> 有可信的未来用途才保留，有旧条目先更新；按作用域归位，按漏取后果和成本决定加载。MEMORY.md 只收确需全局可见、且无专门归宿的例外。
